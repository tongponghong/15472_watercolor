A4: Final Project by Ollie Arrison and Tunger Hong

Our goal for this project was to replicate the watercolor effect, as described in the paper Art-directed watercolor stylization of 3D animations in real-time.

Command-line Arguments

In addition to the typical arguments, you must specify the paper texture which is layered over the result within the final compute shader:

  • --scene scene.s72 --E 0.0 --paper path/to/paper.png

Code Organization + Render Passes

We introduced 2 additional render passes for our renderer to apply all the compute shaders and stylizations necessary to produce the watercolor effect.

(Before) Barrier 1:

We derive all of our color image and control image output from the object fragment shader. The color image is just the direct outColor, and the control image is randomly generated noise based on fractal brownian motion and the position of the vertices from the vertex shader. The depth image is derived from the object data and we use the swapchain_depth_image that is included in tutorial.cpp from the nakluV tutorial. The blurred and bled images are both prepared to be in the right format (VK_IMAGE_LAYOUT_GENERAL) as outputs of the blur and bilateral blur shaders.

(Before) Barrier 2:

The blurred image and bled image are now switched from being written to to being read from since they are now inputs into the stylization shader. Final output is now being prepared to be in the correct format (VK_IMAGE_LAYOUT_GENERAL)

(Before) Barrier 3:

The final image is now changed to be VK_IMAGE_LAYOUT_TRANSFER_SRC_OPTIMAL so that it is ready to be copied to the swapchain image Swapchain image output is now being prepared to be in the correct format (VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL)

Pipeline Organization

ObjectsPipeline

The setup of the objects pipeline was mostly kept the same. Within the fragment shader, we aimed to replicate the watercolor reflectance model, as described in the paper Art-directed watercolor stylization of 3D animations in real-time. Rather than interpreting lighting through a physically-based model, we used water dilution to represent lighter or darker areas. This matches how artists use water to dilute the paint, resulting in lighter values. The dilution area was calculated by summing over the lights. The dilution area can intuitively be thought of then as all the area the light touches on a specific surface/mesh. This is not to be confused with the dilution variable, which controls how strongly the color gets diluted towards the paper color.

The cangiante effect is a non-realistic shift in color as the value shifts from dark to light. Within the paper, this is calculated by adding the cangiante color associated with a given weight to the original scene color. Although this method results in a color shift as the color goes from light to dark, it doesn't entirely capture the transparency-based layering of watercolor paints. Often painters begin by applying a thin layer of blue paint, which appears darker when layered over with the true color of the object in the scene. In order to achieve this, I used the equations for alpha over, setting the background color to the cangiante color, the background opacity to the cangiante strength, the foreground color to the base color, and the foreground opacity to the dilution area.

ComputePipeline

The ComputePipeline directs the Gaussian Blur shader (gaussian.comp). Since it only involves one input image and one output image, it has 2 bindings. Since the paper suggested using a constant and small kernel size, the kernel was created using the python script computeKernel.py. The result of the gaussian filter over the scene can be seen below.

BleedPipeine

The BleedPipeline directs the 4D Bilateral Blur shader (bilateral.comp). Since there are 3 input images and 1 output image, it has 4 bindings. The goal of the bilateral filter is to replicate the bleeding seen in watercolor.

StylePipeline

The StylePipeline is the final pipeline that directs the final stylization shader (style.comp). Since there are 5 input images and 1 output image, it has 6 bindings total.

Evidence

To test the performance of our implementation, we decided to measure frame time based on the maximum radii of Gaussian blur and 4D joint-bilateral filtering effects, and we took into account the amount of geometry present in a scene.

Overall, neither of our implementations seem to have substantial effects on our frame time performance as the frame time remains real-time. It seems that both the bilateral blur filter and gaussian blur filter have similar increases in frame time as the kernel size increases. However, the gaussian blur starts having a significant performance difference at much smaller kernel sizes than the bilateral blur. One way we thought of optimizing our work for future projects is by implementing a two pass method for our Gaussian blur similar to the Bilateral Blur. In addition, instead of having several different kernel constants, we can have the CPU compute the matrices and send them out in a buffer so that the blur can be adjusted by the user during the program.
